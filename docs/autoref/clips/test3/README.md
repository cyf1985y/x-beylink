# test3 影片重跑（使用者上傳的 beyblade_referee_test3.mp4）

**影片性質**：560×590、30 fps、72 秒（SHA-256 前 16 碼 `5601e673573a84ba`）。不是手機直拍，而是舊版離線工具的疊圖螢幕錄影：畫面上有綠圈、SPIN／STOP 標籤、黑色判定橫幅、LIVE／DONE 狀態列，中段有 UX 過場與字幕，結尾是播放器。對應規格 5.1 的「影片 3」（7 局：出界、出界、轉停、出界、出界、轉停、出界）。影片本身未納入 Git，請放在任意路徑後以下列指令重跑。

```sh
node --experimental-strip-types docs/autoref/tools/run_clip.ts <path>/beyblade_referee_test3.mp4 docs/autoref/clips/test3/calib.json docs/autoref/runs/test3
```

**校正**：背景為全片逐像素時間中位數（排除偏差最大的 20% 影格），`background.rgba.gz`；對戰區為紅框自動凸包；極限區（頂端缺口）與左右口袋人工標定；陀螺面積 5,500 px（含疊圖綠圈）。`spin.radiusScale` 覆寫為 0.6 以避開疊圖綠圈（真機不需要）。

## 這次重跑帶出的修正

- 判定後手進來撿陀螺／再發射 → 直接進入下一局 ARMED（原本要「盤內無手且無旋轉 0.5 秒」，連續對戰不會出現）。
- 開局確認窗改成「兩顆都在對戰區、沒有量到停止、期間各至少量到一次旋轉」；發射瞬間模糊量不到角度是常態。
- 待機時沒偵測到手、兩顆已在盤內旋轉 0.6 秒 → 備援開局（`autoStartWithoutHand`）。
- 手提前進入時，只存在不到 `handEarlyMinCandidateSec`（0.1 秒）的進區／疑似停止不當候選（剪接、閃爍防護）。
- 大部分像素落在區域圖外的陀螺尺寸物件（字幕、器材）不是陀螺候選（`beyInsideMinRatio`）。
- 長延遲比對改以秒計（`longLagSec` 0.27 秒），60 fps 自動隔 16 格；隔太久量不到時退用一半的延遲。
