## 這支影片帶出的修正（修正前：先誤判轉停，正確的極限終結根本沒被判到）

1. **角度≈0 不等於停轉（30 fps 混疊）**：紅陀螺在 4.6–5.1 秒與 9.4–9.9 秒明明全速旋轉，極座標角度差與長延遲差都≈0，峰值 0.95 以上——每格剛好轉整數個對稱週期，任何延遲都是整數倍，長延遲比對救不了。但這段期間遮罩內前後格像素平均絕對差有 3–5 灰階，而真正靜止的陀螺（口袋裡的白陀螺）只有 0.02、背景雜訊底 0.04。新增 `spin.stillDiffMax`（0.6）：像素變化扣掉本格雜訊底後超過此值，角度讀數≈0 也只能是「未知」，不是停止。
2. **還在快速平移就不可能已停**：白陀螺沒有花紋，極座標比對常讀到 0°，但它每格移動 5–6 px（每秒 6 個半徑以上）。新增 `spin.movingRadiusPerSec`（2.5）：平移速度（以 `speedWindowSec` 0.2 秒的位置歷史算）達此值一律視為旋轉中。
3. **重複格改看整張畫面**：原本「單顆陀螺前後格幾乎相同」就當重複格，但壓縮影片裡靜止的陀螺本來就逐位元相同，會永遠判不出轉停；改成整張畫面平均絕對差低於 `frameDupMax`（0.05）才是重複格。
4. 停轉後的滾動：像素在變（邊緣平移）期間視為未知，等它停定才累計停止確認——停止時間會晚個零點幾秒，換來不把混疊的高速旋轉判成停轉。

## 對實地部署的提醒

- 這支是側拍：遠端陀螺較小、斜坡與盤壁在影像中重疊，極限區只能靠「陀螺消失」確認。規格要求的正上方俯拍可以直接看到口袋，會穩很多。
- 30 fps 是混疊主因；手機拍 60 fps（多數手機支援）會讓角度法在高速段也有意義。
- 白色陀螺在白盤上是最難的組合；陀螺頂面有花紋、盤面與陀螺顏色有對比時，轉停判定才可靠。
- 單局影片只能說「這一局判對、沒有誤判」，不能當準確率；請多錄幾局並附每局正確答案。
